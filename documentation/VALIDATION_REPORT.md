## 2. Independent Python Validation Methodology

Pipeline 2 enforces five deterministic verification gates on every generated curriculum:

### 2.1 Coverage Score Formula
$$\text{Coverage Score} = \left( \frac{\text{Count of Covered Mandatory Ground-Truth Requirements}}{\text{Total Count of Mandatory Ground-Truth Requirements for Role}} \right) \times 100$$
To achieve coverage, a generated learning module must explicitly reference the unique Requirement ID or match the key operational concepts of that requirement within its objectives, tasks, or checklists.

### 2.2 Traceability Score Formula
$$\text{Traceability Score} = \left( \frac{\text{Count of Module References Linking to Valid Document Chunks}}{\text{Total Count of Module Source References}} \right) \times 100$$
Every citation is verified against SQLite table `document_chunks`. If a citation references a non-existent document code, an invalid section number, or an unapproved document version, it is flagged as an ungrounded reference.

### 2.3 Jaccard Module Redundancy Check
$$\text{Jaccard Similarity} = \frac{|T_A \cap T_B|}{|T_A \cup T_B|}$$
Where $T_A$ and $T_B$ represent token sets of distinct learning modules within the same plan. Any pair with Jaccard Similarity $> 0.70$ is flagged as a duplicate module.

### 2.4 Prerequisite Sequence Validation
Directed acyclic graph traversal verifies that no advanced module is scheduled in Stage 1 or Stage 2 if its prerequisite foundational requirement is scheduled in Stage 3 or Stage 4.

### 2.5 Policy Precedence Hierarchy Resolution
When conflicting requirements are detected, Pipeline 2 applies a 7-tier strict precedence rule:
1. **Tier 1:** Executive Airworthiness Directives (`AD-*`)
2. **Tier 2:** Avionics Cybersecurity & Defense Policies (`SEC-*`)
3. **Tier 3:** Corporate Flight Safety Standards (`SAF-*`)
4. **Tier 4:** System Engineering Standard Operating Procedures (`SOP-*`)
5. **Tier 5:** Flight Operations Manuals (`OPS-*`)
6. **Tier 6:** Technical Training & Tooling Guides (`TRN-*`)
7. **Tier 7:** Departmental Memoranda & Historical FAQs (`MEMO-*`)
In intra-tier conflicts, the document with the newest `effective_date` strictly supersedes older versions.

- **Case CP-01: Dual Remote Work Policies**
  - *Conflict:* Legacy SOP `SOP-OPS-2021-02` (issued 2021) permitted unrestricted personal hardware usage on remote engineering workstations. Modern Security Standard `SEC-POL-2024-01` (Tier 2, issued 2024) strictly mandates hardware-isolated, company-issued secure laptops with YubiKey FIPS tokens.
  - *Precedence Execution:* `SEC-POL-2024-01` (Tier 2, Security) strictly supersedes `SOP-OPS-2021-02` (Tier 4, Operational SOP). Furthermore, the 2024 effective date supersedes 2021.
  - *Result:* The validation engine verified that generated Module 1.4 enforced the YubiKey FIPS requirement and flagged the legacy SOP as superseded.

- **Case CP-02: Flight Software Testing Coverage Thresholds**
  - *Conflict:* Department Memo `MEMO-SW-03` (Tier 7) suggested 85% statement coverage is acceptable for test sprints. Airworthiness Directive `AD-ENG-2024-04` (Tier 1) mandates 100% Modified Condition/Decision Coverage (MC/DC) for Level A flight controls.
  - *Precedence Execution:* `AD-ENG-2024-04` (Tier 1) decisively overrides `MEMO-SW-03` (Tier 7).
  - *Result:* The onboarding plan strictly enforces 100% MC/DC Level A verification.
